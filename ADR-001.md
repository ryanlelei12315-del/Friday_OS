# ADR-001: Agent Runtime Architecture

## Status
Proposed

## Context
The current FridayOS implementation lacks a stateful, autonomous execution controller in its main loop. The active voice pipeline acts as a simple conversational chatbot with direct tool execution. If a tool fails or needs multiple steps, the agent cannot handle plan generation, execution assertions, or recovery.

## Problem
How can we enable Friday to handle multi-step goals, observe output, verify correctness, and recover from intermediate failures without blocking the real-time voice pipeline?

## Options Considered
1. **Direct LLM Chain (Option 1)**: Let the LLM handle all planning and tool calling in a single-shot prompt context. Highly fragile, prone to context bloat, and lacks verification states.
2. **Decoupled File Watchdog Loop (Option 2)**: Maintain the current pattern where the agent writes a file and a separate script triggers local pyautogui. Fragile, difficult to coordinate, and has no direct telemetry back to the voice agent.
3. **Stateful Orchestrator and Planner (Option 3)**: Introduce an explicit state machine running an Observe-Plan-Act-Verify-Reflect loop driven by a structured `TaskState` schema.

## Decision
**Option 3: Stateful Orchestrator and Planner**. We will implement a dedicated Orchestrator module managing a Pydantic-validated `TaskState` object, running independently of the real-time voice pipeline.

## Consequences
* **Positive**: Enforces deterministic state transitions, facilitates self-healing, supports human-in-the-loop validation, and prevents context bloat.
* **Negative**: Increases codebase complexity and introduces additional processing overhead for simple commands.

## Rejected Alternatives
* **Option 1 (Direct LLM Chain)**: Rejected because it does not support self-healing or validation guarantees.
* **Option 2 (Decoupled File Watchdog)**: Rejected because it is highly fragile and lacks direct communication channels back to the voice agent.

## Future Revisit Conditions
Revisit if the overhead of state machine transitions significantly increases execution latency for low-risk, single-step tasks.
