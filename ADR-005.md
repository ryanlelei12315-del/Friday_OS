# ADR-005: Windows Computer Control Strategy

## Status
Proposed

## Context
The current computer-use strategy is fragile. Opening apps relies on fuzzy searches against Start Menu links, and terminal actions execute raw shell commands. The local pyautogui macro loop relies on Ollama guessing mouse coordinates, which is highly brittle and environment-dependent.

## Problem
How do we establish a deterministic, reliable, and robust strategy for Friday to control the Windows operating system?

## Options Considered
1. **Visual-Only (Option 1)**: Control Windows solely using screenshots, OCR, and coordinate-clicking. Highly fragile, slow, and prone to failure on monitor scaling shifts.
2. **Raw Subprocesses (Option 2)**: Execute everything via command line and PowerShell. Fast, but lacks any ability to interact with GUI applications or menus.
3. **Structured API Hierarchy (Option 3)**: Prioritize deterministic API calls and Accessibility Trees (UI Automation) before falling back to visual coordinates.

## Decision
**Option 3: Structured API Hierarchy**. We will establish a strict hierarchy of operations for computer use:
1. **API / Command Line** (PowerShell, processes, filesystem).
2. **Accessibility Tree / UI Automation** (pywinauto, MSAA, UIA) for structured GUI element mapping.
3. **Stateful Browser DOM** (Playwright) for web applications.
4. **Visual Coordinates / VLM / OCR** (screenshots, pyautogui) only as a last fallback when APIs or Trees are unavailable.

## Consequences
* **Positive**: Minimizes brittle visual guessing, increases speed, and ensures Friday works reliably across different screen resolutions and DPI scaling factors.
* **Negative**: Requires writing more complex, platform-specific code utilizing pywin32 and pywinauto libraries.

## Rejected Alternatives
* **Option 1 (Visual-Only)**: Rejected because coordinate clicking is notoriously fragile and fails immediately on minor resolution shifts.

## Future Revisit Conditions
Revisit if lightweight, local visual models become fast and reliable enough to match the speed and determinism of native Windows APIs.
