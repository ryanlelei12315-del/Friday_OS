# ADR-008: Security and Permission Model

## Status
Proposed

## Context
The current FridayOS implementation has no security boundaries or permission gates. Any tool (e.g. deleting files, terminating processes, executing PowerShell blocks) can be invoked automatically by the LLM without user knowledge or approval.

## Problem
How do we protect the user's host machine from accidental or malicious destructive operations while maintaining a smooth user experience?

## Options Considered
1. **Unrestricted (Option 1)**: Let the agent execute everything silently. Unacceptable security risk.
2. **Strict Prompts (Option 2)**: Instruct the LLM in the system prompt to "always ask before deleting". Brittleness: LLMs easily bypass prompt instructions or suffer from instruction drift.
3. **Capability-Based Gateways (Option 3)**: Intercept all tool calls in a secure system layer, enforcing strict risk-level policies and approval prompts.

## Decision
**Option 3: Capability-Based Gateways**. Friday will enforce a secure policy gateway intercepting all tool runs. Medium risk tools require verbal confirmation, and high/critical risk tools require interactive GUI click approvals.

## Consequences
* **Positive**: Guarantees system safety, protects files and credentials, and provides a clear audit trail of all agent actions.
* **Negative**: Introduces minor friction to the user experience for complex tasks.

## Rejected Alternatives
* **Option 2 (Prompt Limits)**: Rejected because system prompt constraints are easily bypassed and do not provide deterministic security guarantees.

## Future Revisit Conditions
Revisit if we deploy containerized or sandboxed Windows virtual environments, which would allow us to safely run high-risk commands silently.
