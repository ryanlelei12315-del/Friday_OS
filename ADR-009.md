# ADR-009: Voice Pipeline and Interruption Architecture

## Status
Proposed

## Context
While FridayOS uses LiveKit and Gemini Realtime, it suffers from minor speech latency. Additionally, the context tracker's output is logged in the console but never injected into active conversation sessions, leaving the agent blind to desktop activity.

## Problem
How can we minimize speech latency, support clean conversational barge-ins, and ensure Friday has real-time visual awareness during active conversations?

## Options Considered
1. **Periodic Prompts (Option 1)**: Re-initialize the LLM session with updated prompts whenever the clipboard or window shifts. High latency, high cost, and breaks conversational continuity.
2. **Context-on-Request (Option 2)**: Only query the tracker when Friday explicitly executes a "get_system_context" tool. Low cost, but prevents Friday from being proactive.
3. **Dynamic Session Instructions (Option 3)**: Keep a persistent WebRTC session but update its active system instructions dynamically in the background on context changes.

## Decision
**Option 3: Dynamic Session Instructions**. We will leverage LiveKit's capability to update the session's active system prompt in the background. The Context Engine will push updates whenever the active window or clipboard shifts.

## Consequences
* **Positive**: Friday possesses real-time awareness of active desktop windows and clipboards, and can respond conversationally without latency or context breaks.
* **Negative**: Requires handling rapid context changes to prevent flooding the session with redundant instructions.

## Rejected Alternatives
* **Option 1 (Periodic Re-init)**: Rejected because re-initiating WebRTC sessions causes noticeable audio dropouts and breaks conversational continuity.

## Future Revisit Conditions
Revisit if the LiveKit Agents SDK implements native, multi-modal screen-streaming interfaces, allowing direct video frame streaming to the VLM.
